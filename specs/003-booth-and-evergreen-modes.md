# 003. 부스용·상시용 운영 모드 분리

- 상태: accepted
- 소유: WINGS 팀
- 갱신일: 2026-08-28

## 문제와 목표

WINGS는 팝업 부스에서 빠르게 체험하는 방문자와, 평소에 서비스를 재방문하는 사용자를 모두 대상으로 한다. 두 상황은 로그인·저장·안내량·완료 후 행동의 목적이 다르므로 동일한 사용자 흐름으로 제공하면 어느 쪽도 최적화되지 않는다.

목표는 공통 진단 엔진과 디자인 언어는 유지하면서, 진입 경로와 데이터 정책을 부스용·상시용으로 분리하는 것이다.

## 운영 모드

| 구분 | 부스용 (Event) | 상시용 (Evergreen) |
| --- | --- | --- |
| 주 사용자 | 현장 행사 방문자 | 재방문·회원 사용자 |
| 최우선 목표 | 1분 내 체험 완료 | 결과 축적과 재방문 |
| 로그인 | 요구하지 않음 | 결과 저장·찜·기록 접근 시 요구 |
| 데이터 보관 | DB에 `guest` 기록, 브라우저는 현재 세션만 | 사용자 계정과 연결해 저장 |
| 첫 행동 | 사진 진단 시작 | 서비스 소개·로그인 또는 진단 시작 |
| 완료 후 CTA | QR/공유·현장 혜택·상품 보기 | 마이페이지·기록·찜·피드백 |
| 화면 문구 | 짧고 행사 맥락 중심 | 설명과 개인화 맥락 포함 |
| 개인정보 고지 | 사진·결과의 세션 종료 기준 고지 | 저장 목적·보관·삭제 경로 고지 |
| SAZU | 행사 범위에서는 미노출 | 상시용 `/sazu`에서 제공 |

## 경로 결정

| 경로 | 모드 | 역할 |
| --- | --- | --- |
| `/booth` | 부스용 | 행사 시작 화면 |
| `/booth/photo` | 부스용 | 사진 선택 |
| `/booth/analyzing` | 부스용 | 분석 진행 |
| `/booth/survey` | 부스용 | 보정 설문 |
| `/booth/result` | 부스용 | 세션 결과 |
| `/booth/recommendation` | 부스용 | 행사 추천 상품 |
| `/` | 상시용 | 일반 서비스 첫 화면 |
| `/onboarding`, `/photo`, `/result`, `/recommendation` | 상시용 | 계정·저장 가능 진단 흐름 |
| `/sazu` | 상시용 | 사주 분석 |

기존 부스 경로는 전환 기간 동안 유지하되, 행사에서 배포하는 QR은 반드시 `/booth`를 사용한다.

## 사용자 시나리오

### 시나리오 A — 부스 방문자

1. 방문자는 행사 QR을 스캔해 `/booth`를 연다.
2. 로그인 없이 사진 진단을 완료한다.
3. 결과와 현장 맞춤 혜택·추천 상품을 확인한다.
4. 진단 결과는 운영 통계용 `guest` 기록으로 DB에 저장되지만, 방문자는 브라우저 세션이 끝나면 결과를 다시 볼 수 없음을 이해한다.

### 시나리오 B — 상시 사용자

1. 사용자는 일반 도메인의 `/`에서 서비스를 연다.
2. 진단 후 결과를 계정에 저장하거나, 로그인 후 기존 기록을 확인한다.
3. 마이페이지에서 기록·찜·피드백·SAZU 분석을 이용한다.

## 수용 기준

| ID | 기준 |
| --- | --- |
| AC-01 | 행사 QR의 `/booth` 진입은 로그인 화면으로 이동하지 않는다. |
| AC-02 | 부스 흐름은 상시용 마이페이지·SAZU·계정 메뉴를 노출하지 않는다. |
| AC-03 | 부스 결과 화면은 세션 기반임과 결과 재열람 불가를 명확히 고지한다. |
| AC-04 | 상시용 흐름은 저장·기록·찜 기능을 유지하며, 이 기능에서만 로그인 요청을 한다. |
| AC-05 | 부스·상시용은 디자인 토큰과 진단 API를 공유하되, 화면 문구와 완료 CTA는 분리한다. |
| AC-06 | `/preview`에서 두 모드의 모든 진입·완료 화면을 구분해 확인할 수 있다. |
| AC-07 | 부스 경로에서 로그인 redirect가 발생하지 않으며, `diagnosis_requests`에는 `user_id = null`, `requester_type = "guest"`, 세션 난수의 해시만 저장한다. |
| AC-08 | 상시용 SAZU는 출생 정보 보관 정책을 002 명세와 동일하게 따른다. |
| AC-09 | 부스 `guest` 진단 기록은 이후 로그인해도 회원 기록으로 이전하지 않는다. |
| AC-10 | 부스 결과·추천 화면에는 홈 이동, 로그인 유도, 특가 알림, 찜 기능을 노출하지 않는다. |

## 구현 경계

- 화면 컴포넌트는 필요한 경우 재사용하되, 운영 모드는 경로와 명시적인 `mode` 값으로 구분한다.
- 부스 guest 기록은 브라우저가 Supabase에 직접 쓰지 않고, Vercel Function이 `SUPABASE_SERVICE_ROLE_KEY`로 저장한다.
- 부스 여부를 브라우저 User-Agent, 화면 크기, 쿠키로 추론하지 않는다.
- 행사 QR 또는 명시적 `/booth` 경로로만 부스 모드에 진입한다.
- 상시용의 인증·저장 정책을 부스 경로에 예외적으로 섞지 않는다.

## 후속 결정 필요

- 부스 결과 완료 후 QR 공유, 쿠폰 코드, 카카오톡 공유 중 사용할 CTA
- 상시용에서 진단 시작 전에 로그인을 요구할지, 결과 저장 시점에만 요구할지
- 기존 `/`, `/onboarding` 경로를 상시용으로 완전히 전환하는 배포 시점
- 행사 종료 뒤 `/booth` 경로의 유지·리디렉션 정책
