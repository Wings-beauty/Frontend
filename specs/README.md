# WINGS Spec-Driven Development

WINGS의 기능 변경은 구현 전에 명세를 먼저 작성·검토한다. 명세는 제품 의도와 검증 가능한 결과를 한 문서에 보존하기 위한 기준이며, 코드의 세부 구현을 반복하지 않는다.

## 작업 흐름

1. `specs/NNN-feature-name.md`에 문제, 범위, 사용자 시나리오, 수용 기준을 작성한다.
2. 수용 기준이 모호하거나 측정 불가능하면 구현을 시작하지 않는다.
3. 구현은 명세의 수용 기준을 충족하는 최소 변경으로 한다.
4. 완료 전 수용 기준별 검증 결과를 명세의 검증 기록에 남긴다.

## 명세 규칙

- 번호는 생성 순서로 증가한다. 기존 명세를 재작성하지 말고 변경 이력을 남긴다.
- MUST는 출시/행사에 필수인 조건, SHOULD는 품질 목표다.
- 개인정보·로그인·외부 서비스가 연관되면 실패 시 동작과 보관 범위를 명시한다.
- 화면 문구, API 함수명, CSS 구조처럼 쉽게 바뀌는 구현 세부 사항은 명세의 주제가 아니다.

## 상태

- `draft`: 검토 전
- `accepted`: 구현 기준으로 승인됨
- `implemented`: 구현과 필수 검증이 완료됨
- `superseded`: 후속 명세로 대체됨
